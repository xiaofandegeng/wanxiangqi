# 王者万象棋 · 王牌对决研究台：项目总览与架构

记录于 2026-11-13（北京时间）。基线：`main@a33fff5`，同时观察工作区内尚未提交的来源包、阵容规则和 11 月 9 日第 2 场模拟用例。本文是接手地图；旧 README 和阶段报告保留各自的历史口径。

## 产品定位与范围

项目从早期赛事数据站转向教学站，再回到王牌对决研究。当前用户路径是查赛果和选手玩法 → 录入赛前六人、棋手与禁用 → 对照历史和阵容适配。返奖倍数随投入变化，不作为胜率输入。当前有规则对比和实验概率，尚未证明预测质量，也没有自动投币或可靠的实时赛果同步。

## 数据流与权威边界

1. **原始资料 → 来源档案。** 图集链接和原图 → 人工核对日期、场次、六席与独立胜者栏 → JSON 来源包 → [导入工具](../backend/tools/import-prediction-catalog.mjs)。导入校验原件哈希并事务写入；相同键的不同内容会冲突。胜者以外的图中编号不能当名次，作者周汇总不能拆成逐局。来源昵称未确认 UID，不应凭相似名称合并。
2. **来源档案 → 展示。** [CatalogService](../backend/src/prediction/catalog.mjs) 把来源包和数据库来源赛果合并，再按日期、场次补充 [冠军快照](../backend/src/prediction/historical-matches.mjs)。`full_transcribed` 表示来源转写类别，不代表六人名次核验；`winner_snapshot` 可含推断棋手和占位席位，不能当真实阵容、对手名单或参赛分母。部分页面再叠加浏览器本地修改。页面总量不等于数据库写入量。
3. **完整赛果 → 正式统计。** [PredictionService](../backend/src/prediction/service.mjs) 管理完整六人名次的录入、核验、隔离及统计。前三率和均排依赖完整名次；阵容胜率还需要真实使用次数及胜负。常用、作者称擅长、程序推断和实测胜率是不同类型。
4. **赛前截图 → 分析。** 素材先进入证据服务，macOS Vision 生成 OCR 草稿，人工确认昵称和可见条件；[截图分析服务](../backend/src/prediction/screenshot-analysis.mjs) 保存请求、截点与结果。赛后信息不能作为赛前特征。页面的阵容推荐/禁用对比使用前端规则；[后端胜者模型](../backend/src/prediction/winner-model.mjs) 是另一路实验计算，基于历史名单与冠军，不能把前端规则评分解释为已校准概率。

## 实查基线

2026-11-13 读取本机预测开发库和前端代理的 `catalog` 接口：

| 口径 | 实查结果 |
|---|---|
| 工作区来源 JSON | 73 场、49 条来源 |
| PostgreSQL `wanxiangqi_prediction_dev` | 62 场来源记录、372 席；完整赛果表 0 场 |
| `catalog` 合并输出 | 235 场：73 条转写类别、162 条冠军快照；来源计数 45 来自数据库 |

来源 JSON 的 73 场为 10 月 23–29 日 54 场、11 月 6 日 8 场、11 月 8 日 8 场、11 月 9 日 3 场。10 月 31 日至 11 月 6 日这个旧补录窗口中，来源包只有 11 月 6 日有逐局转写；合并输出的冠军快照不能补足其余日期的六人赛果。README 的 54 场和历史模块的 232 场注释都不应作为当前数据库计数。

## 本地运行与维护

在项目根目录分别开两个终端。先启动后端，再启动前端：

```sh
cd backend
npm ci
npm run dev:prediction
```

```sh
cd frontend
npm ci
npm run dev:local
```

后端绑定 `127.0.0.1:8082`，使用 `wanxiangqi_prediction_dev`，启动会应用迁移；前端绑定 `127.0.0.1:5174`。健康探测：`curl -fsS http://127.0.0.1:5174/api/v1/ready`。本机开发模式由 Vite 代理为指定只读请求携带凭证；直连管理接口及写入仍受鉴权保护。凭证保存在后端本地文件，不进前端构建。

覆盖检查可在仓库根目录运行 `node backend/tools/prediction-coverage.mjs 2026-11-06`，只统计来源包。导入使用 `node backend/tools/import-prediction-catalog.mjs`；它会写库，且限制目标为预测开发库或专用测试库。重新导入前应先核对已有场次的内容哈希，不能用覆盖旧记录解决冲突。后端用 Node test runner，前端用 Vitest；前端构建用 `npm run build`（含类型检查）。

## 后续核查重点

- 对齐来源包、数据库、冠军快照和页面本地覆盖，页面分别标识各口径；优先核实快照的逐场出处及缺失字段。
- 审计时间截点：数据库查询有 `available_at` 和日期限制，但 `catalog` 另行合并本地 JSON 与冠军快照。对比数据、正式统计与模型训练需分别验证过滤范围，不能从 SQL 有过滤推断整个合并结果均满足历史截点。
- 核对棋手和阵容字段的观察来源，区分真实选择、赛后成型、作者标签、程序推断及未知；补够逐局分母再做禁用分组和滚动回测。
