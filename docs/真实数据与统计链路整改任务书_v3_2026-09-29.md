## 4. 实施顺序与修改要求

### P0-A：先修测试隔离，防止继续污染

- StorageEngine 支持显式注入存储目录或 repository；导入模块不得自动写业务文件。
- 测试默认使用临时目录和独立测试数据库；数据库集成测试必须校验目标不是开发/正式业务库。
- 需要联网的契约测试与普通单测分开；无法联网应明确 skip 或失败，不能把来源失败视作真实接入通过。
- 增加测试前后业务 storage.json 哈希、业务数据库关键表计数不变检查。测试不得先备份再覆盖业务文件来“模拟隔离”。
- 上轮测试已经写过当前 storage.json。恢复只能依据可靠备份或原始材料；不要拿 HEAD 文件覆盖用户未提交修改，也不要把健康接口数量当完整备份。

### P0-B：停止生成数据进入业务路径，准备可回滚隔离

- 停用两个生成脚本的业务入口；如保留演示用途，移入独立 fixtures，标记 SYNTHETIC，限制只能写 demo/test 存储。
- 清点 PostgreSQL、JSON、进程缓存及持久化快照，逐批生成 dry-run 清单：记录主键、来源、影响人数、统计差异、隔离原因。
- 对已确认的两个生成批次及测试审核记录进行可回滚隔离，原记录与校验哈希留存，不默认永久删除。对其他无证据记录转待核验，不一概认定虚假。
- 人工核验标识不能由导入 JSON 中的 verified:true 直接授予；必须由服务端核验动作或已验证的来源流程决定。
- 本文件不授权直接修改生产数据；先完成脚本、备份验证和 dry-run，执行真实清理须有相应授权。

### P1-A：统一数据库与 API

采用 PostgreSQL repository 供所有业务 API 读写；JSON 仅允许作显式导入材料、独立演示数据或有版本的只读缓存，禁止静默替代数据库成为第二套事实库。

- 写入流程：校验 → 同一数据库事务写证据/事实/版本/批次 → COMMIT → 返回成功 → 更新或失效缓存。
- 异常向上返回；同步失败不能只 console.error 后返回成功。异步任务若必要，返回 202 与 jobId，完成状态单独查询。
- 事务是全成或全败的边界，不能用多个未等待 Promise 代替。[PostgreSQL 17 事务文档](https://www.postgresql.org/docs/17/tutorial-transactions.html)
- 空表必须产生空结果，不能保留旧 JSON 数组；启动恢复失败不得标 POSTGRESQL_LIVE。
- 正式模式数据库不可用时 readiness 返回 503；liveness 可仍正常。只读旧缓存必须明确 stale、快照时间和范围；写入必须失败。
- health/readiness 报告真实检查结果，不读取 JSON 中残留的引擎文案。公开接口不暴露连接凭证和内部错误详情。
- 迁移有版本记录，和启动逻辑分离；配置通过环境变量传递，提供不含真实密钥的示例。
- 复核后端启动命令、代理端口和实际运行版本，排查 67/1337 与 79/212 的差异，提交根因及修复证据。

### P1-B：建立可追溯的数据模型

优先演进现有表，不要求整体重写框架。字段可调整命名，但必须表达以下语义：

| 实体 | 必须表达的信息 |
|---|---|
| 数据来源 | sourceId、类型、能力、授权/使用范围依据、状态、最后尝试/成功时间、错误摘要 |
| 原始材料 | sourceId、原始记录键、fetchedAt/capturedAt、内容哈希、受控存储位置、解析器版本 |
| 玩家身份 | 内部 playerId、来源内 externalPlayerId、区服/平台、昵称变更；不能靠昵称合并 |
| 玩家属性 | 天梯积分/段位及其来源、时间；赛事积分与赛事排名单独字段；未知为 null |
| 对局参赛记录 | 来源、外部对局 ID、玩家身份、模式、版本、参赛人数、名次、matchTime、证据引用 |
| 记录版本 | revision、acceptedAt/availableAt、supersededAt、核验状态、操作者或来源规则 |
| 阵容快照 | 结构键、来源、版本、模式/区服/段位范围、窗口起止、样本单位、指标、采集时间 |
| 同步任务 | 输入范围、游标/分页、开始结束、读取/新增/重复/失败数量、状态、错误 |

幂等键至少包含来源、外部对局 ID、外部玩家身份；同一局多个玩家不能互相覆盖。没有外部对局 ID 时使用受控证据键并识别重复材料，不能仅按时间和昵称武断合并。

名次需与实际模式规则一致。现有 1～6 校验仅在确认六席模式时适用，不外推至所有来源；未知模式或参赛人数先待核验，不凭推测统一改成另一人数。

### P1-C：最小真实纵向闭环

先选一个有实际材料的来源，实现：原始材料 → 候选解析 → 核验 → PostgreSQL → 玩家统计 API → 玩家详情。

- 保留材料与记录逐字段映射；材料不能证明的回合数、阵容、积分保持 null。
- OCR 只产候选；人工核验界面显示原图与候选，不自动确认全部字段。
- 身份不确定则不归并到已知玩家；不通过昵称关键词猜打法。
- 增量同步记录游标并防重入；失败保留上次有效数据但显示失败/过期，成功时间不能在失败时更新。
- 连续两次运行证明幂等，再验证一次失败及恢复。需令部分记录确实来自第二次真实增量，若来源无更新则如实证明无新增。
- 若没有任何可用真实材料，完成工程链路并交付“真实接入未完成”的阻塞清单，不拿 fixtures 通过真实来源验收。

### P2-A：统一统计口径，处理时间和更正

在服务端定义唯一统计服务，列表、详情、导出和分析共用；数据库约束与代码校验一致。

有效个人参赛记录集合 S：身份一致、已核验、非合成、证据链有效、在模式/版本/区服/来源/时间范围内，且每个稳定记录键只取适用版本。

- N = |S|；登顶率 = 名次为 1 的数量 / N；前三率 = 名次 ≤ 3 的数量 / N；均名 = 名次总和 / N。
- N=0 时比例、均名为 null；N>0 且没有夺冠必须为 0，不能用 `||` 替换零值。
- 时间窗口统一采用 [from, to)，内部 UTC，界面明确时区；无效时间参数返回 400，不静默忽略。
- 赛前截点 t 要求 matchTime < t 且 availableAt ≤ t。availableAt 表示记录通过系统核验并可使用的时刻，不能由 matchTime+15秒伪造；采集时间单独保存。
- 更正采用版本历史，不覆盖旧事实。按截点取当时可见版本；后来更正不能改写历史回测输入。撤销记录同样保留状态变更时间。
- 未知模式不能混进指定模式；未知 availableAt 不能回退到比赛时间参与赛前统计。
- 返回 N、分子计数、窗口、模式、数据覆盖说明；低样本提示的阈值配置化，不以阈值证明预测准确。
- 个人被收录战绩可能不完整，标签使用“已收录 N 局”，不得称“全部历史”。

### P2-B：阵容汇总保持来源语义

- 百分数究竟为 0～1 还是 0～100 必须由来源契约确定并验证范围，不能猜测。
- 缺失率、均名、样本量为 null；不得补 0、3.5 或固定百万样本文案。
- 保留原始窗口、模式、版本、数据截止时间。采集成功时间不等于数据更新时间。
- T0/T1/T2 只能保留来源明确提供的评级，或另名展示有版本说明的内部评分；不按返回顺序生成权威评级。
- 不合并重叠阵容的样本，不把多个窗口/来源直接平均。只有明确不重叠、口径一致且有原始计数时才计算合并比例。
- 只获得来源汇总时不能反推逐局名次，也不能从四舍五入后的百分比反推出精确胜场。

### P2-C：前端取消虚构分析，调整展示

- 移除生产路径对 mock/pro-players、mock/match-history 的引用和未知玩家默认战绩。
- 页面读取统一统计 API，携带 playerId、模式、版本、窗口、截点；取消过期请求或忽略旧响应，筛选状态可追踪。
- 先交付历史描述分析：样本数、登顶率、前三率、均名、近期名次、基于真实记录的阵容使用分布。
- 缺数据展示“暂无已核验战绩”；接口失败展示失败，不能伪装空结果或改用静态数字。
- 玩家页把赛事积分与天梯积分分开；阵容页展示第三方来源和快照；核验、同步日志放管理页。
- 使用表格和清晰筛选，去掉“绝对压制”“真实推演”“顶级大师”等无证据判断。保留 v2 的克制视觉要求。
- 当前胜率推演和基于它的下注/支持建议先关闭。归一化手写权重不是经过验证的获胜概率。

预测恢复不作为本轮完成条件。后续如单独开发，须有时间切分的训练/验证、同场分组防泄漏、独立测试集、基线、校准与误差报告；保留模型和输入快照版本。未获证据前不得标“真实胜率”。

真实来源验收不能用自编响应代替；mock 响应只能验证解析、错误处理和边界。基础单测通过与真实接入通过分别报告。

## 6. 交付物与完成状态

必须提交：

1. 修改代码、迁移、示例配置、可复跑测试与命令。
2. 数据隔离 dry-run、影响清单、备份校验及回滚方法；未获授权的清理标“待执行”。
3. 来源接入报告：能力、使用范围依据、已验证字段、限制、最后实测时间；清楚区分已实现/未配置/受阻。
4. 至少一条真实材料贯穿原始记录、数据库、统计、API、页面的映射，以及 V07/V14 抽样核对表。
5. V01～V18 逐项证据，不得只写“全部通过”；注明失败与未执行原因。
6. 数据库和 API 不一致的根因；测试覆盖业务文件的修复与回归证明。
7. 前端截图覆盖正常、空数据、失败、过期和筛选状态。

完成状态拆成三项：工程链路完成、个人真实战绩接入完成、第三方阵容接入完成。可以部分交付，但不得把后两项受阻包装成全部完成。
