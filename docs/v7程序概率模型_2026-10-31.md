# 后端程序概率模型

2026-10-31。概率由后端 `winner-model.mjs` 确定性计算；不由聊天助手填写、修改或挑选数值。不调用大模型生成概率。当前仅为显式启用的来源实验模型。

## 实现与输入

模型版本 `source-roster-luce-l2-v1`。借鉴 [Luce／Plackett–Luce 选择概率](https://hturner.github.io/PlackettLuce/articles/Overview.html)：每名来源昵称有强度 θ，本场六人中的冠军概率为 exp(θᵢ) / Σexp(θⱼ)。这里只拟合第一名，不虚构剩余完整排名。

本项目使用自己的L2正则实现（不是引用R包的伪比较实现）：最小化所有历史场次的冠军负对数似然，加 λ/2 × Σθ²；λ固定2，最多400步，梯度阈值1e-8。固定配置不按这次诊断结果调参。未知昵称强度使用0先验，其他玩家概率仍按同场强度归一。样本少会向相同强度收缩。

输入为数据库可见的完整六人名单和唯一冠军。按matchId组成一场，排除不完整名单；截止同时沿用catalog对收录可见时间、日期、来源状态和原件可恢复性的筛选，模型层再次排除同日无精确时刻及未来比赛。相同昵称仅为来源内句柄，不跨别名合并。

不使用：当前返奖率、名单席位号、最终阵容、作者评价、段位分。当前棋手／禁用／版本未知时不会编造特征；也尚未实现这些条件的训练。历史模式版本未完全核实，不能称为同模式同版本的可靠预测。

## 程序输出及复算

截图分析POST加入 `experimentalProbability:true` 时返回 `EXPERIMENTAL_PROBABILITIES`；不启用时仍可只查资料。赛后标记图片不生成实验概率。前端默认勾选程序实验计算，仍须人工确认六席。

每次分析保存六人确认输入、训练场次ID、参数、模型配置、训练数据SHA-256、截止时间、概率、诊断和模型版本。`GET /api/v1/admin/prediction/screenshot-analyses/:id` 可读取当时快照，需要管理凭证；原截图被隔离后禁止读取。网页“已保存分析编号”可恢复展示，读取不重新训练。

命令行与网页调用同一后端程序（在backend目录）：

```sh
node tools/run-screenshot-probability.mjs \
  --draft 61c3ee4f-dfaf-4e0e-82fe-2dab1a8af4da \
  --request-file ../docs/prediction_artifacts/user-live-20261031-1600-analysis.json
```

命令读取本地预测开发凭证，不打印凭证；会在开发库新增分析快照。请求文件可为六人确认对象，或包含 `input` 的测试记录。不得手写概率作为输入。

## 离线诊断：目前没有预测优势证据

以每天为测试块，仅以前日赛果训练；首日8场没有训练历史不计入诊断，剩余46场。真实比赛发生时的材料可得性未被历史记录证明，因此这属于**事后按比赛日滚动诊断，不是历史当时可得回放，也不是前瞻验证／概率校准**。

| 指标 | 当前模型 | 六人均分基线 |
|---|---:|---:|
| 平均对数损失（越低越好） | 1.810778 | 1.791759 |
| 多分类Brier（各席平方误差之和，越低越好） | 0.841127 | 0.833333 |
| 最高概率命中折算 | 0.123188 | 0.166667 |

目前模型未优于均分，页面显著提示。并列最高按1/并列人数记命中，避免作者将冠军排在第一席造成均分基线100%命中的假象。诊断集小且事后采集，不据此承诺以后表现。

`calibrated:false`，分配保持ABSTAIN。概率和报价分开，不因某个估计超过报价保本阈值就自动生成投比。后续需要更多独立场次、账号与模式版本确认，以及前瞻评估。
