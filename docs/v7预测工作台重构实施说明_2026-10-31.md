# v7 预测工作台重构实施说明

## 本轮实现

用户指令：先修改重构，稍后提供真实数据；新增来源线索抖音软柿【万象棋】，抖音号76823812617。

主页面改为总览、场次赛果、选手统计、赛前研究、数据录入。v6教学主页面退出主入口，课程/图鉴的独立资料路由不删除数据。旧v2–v5 API不恢复，不读取archive_legacy。README已替换为当前启动方式与能力边界。

新增0010迁移，独立prediction_matches保存标准化六席JSON、原件引用、内容摘要、核验时间与核验人、隔离时间与操作人。prediction_runs保存研究运行截止点、模型版本和结果。未在业务库运行迁移。

全部新API位于 /api/v1/admin/prediction/：GET matches/stats/runs；POST matches、matches/:id/verify、matches/:id/quarantine、estimate。已有Bearer管理鉴权覆盖全部读写。JSON请求256KB上限。

原件须可恢复且未隔离才能录入，已核验原件才能放行赛果；统计时再次检查原件状态和可恢复性。只含冠军、六席不齐、重复排名、同场重复UID、未来或无时区的赛果拒绝。缺UID可保留但不合并为跨场选手统计。同名、跨平台区服、不同模式版本分开。来源键内容幂等；同来源键不同内容、自然场次键重复均409。错误记录可隔离，不能悄悄覆盖。

平滑平均名次研究基线：每人至少3场同模式同版本有效记录；平滑均值=(名次总和+3×3.5)/(场数+3)，softmax(-平滑均值)归一化。选手须同平台区服，六人不重复。输出始终 calibrated=false，明确未经独立回测；不足不返回概率。仅使用 playedAt < cutoff 且 verifiedAt <= cutoff 记录。当前不是历史回测工具、不是实测可靠的夺冠胜率。

新启动命令 backend npm run dev:prediction 固定独立开发库/8082，令牌首次写本机gitignore文件；frontend npm run dev:local 同步8082。server.js在连接PG前拒绝未显式允许的业务库自动迁移，避免此前 .env 回退误连。

## 第二阶段：来源资料接入（用户指令“开始改造”）

### 已完成

- 新增 `/research/sources` 与导航入口，复用已配置管理凭证。录入表在已有资料时默认收起，优先展示资料台账；支持手机单列、电脑双列表单，表格在自身容器内滚动。
- 新增0011独立表prediction_observations，不更改已应用迁移。来源唯一键、内容摘要、原件引用、获取/复核/隔离时间与操作人均留档。
- `ROSTER_WINNER`：完整六人参赛名单＋冠军所在位置；名单位置不作排名，其他五人名次明确未知；拒绝传入推测rank字段。
- `PLAYER_AGGREGATE`：原始昵称、可空UID、明确整数出场数/登顶数/前三数、可空平均名次。必须0≤登顶≤前三≤出场，均值1–6并与计数的可实现范围相容（允许原图一至两位小数舍入）；不按百分比倒推分母。录入框不预填出场数或零胜场，要求人工填写。
- 来源链接限定无凭证HTTP(S)，仅作人工复核链接；不自动抓取远端，不访问隐藏接口。
- 两种资料均有窗口、模式、来源作品、原件定位；版本、平台和区服未确认可留空。不凭昵称跨资料合并。同资料相同昵称有不同明确UID可保留，未知UID重名须先复核。
- 全部读取与操作仍受Bearer鉴权。保存要求原件存在可恢复、未隔离；确认资料还要求原件已核验。原件后来失效时，台账如实标不可引用；资料可隔离且留审计。
- **即使资料已复核，也不进入prediction_matches，不参与computeStats或estimate。** 汇总窗口重叠、同一比赛被不同作品覆盖，不产生分母重复。没有实现从资料自动推导完整赛果。
