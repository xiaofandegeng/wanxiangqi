## 1. 阶段目标及边界

本轮不恢复预测胜率、不新增投注建议、不要求任意选手全量历史、不强制增加新框架或重构已通过的数据层。本人材料导入完成，只能称“个人真实战绩人工接入完成”，不能称官方 API 自动同步完成。

### 2.1 获得第一批个人数据的实际路径

**首选：本人授权材料。** 项目方或志愿玩家在自己的设备上登录官方工具/游戏战绩页，提供最近连续的一段逐局记录及必要身份信息。优先最近连续 5 局，包含输赢，不刻意挑选夺冠截图；若只能获得部分记录，页面注明“已收录样本，不代表完整历史”。

**备选：有明确使用范围的赛事逐局结果。** 只有材料明确给出每局时间、选手身份、模式和名次时才作个人参赛记录。只有积分榜不能换算成逐局战绩；赛事模式与排位模式分开。

**后续：获准官方或第三方 API。** 先核实数据能力、账号范围、速率限制、字段口径、公开展示与保存期限，再实现增量同步。没有授权文档时不猜接口、不采集密码或会话 Cookie。

本人查询权限不自动涵盖其他玩家。公开论坛帖子也不自动提供完整身份或复用授权。材料授权范围需区分内部验收与公开展示；只获内部使用许可的数据不能直接上线公开。

## 3. 本轮代码核查发现的承接缺口

这些是面向“真实材料交付”的下一阶段差距，不推翻上一轮四项定向复验结果。

### 3.1 截图页尚未完成原图保存

`frontend/src/views/evidence-verify.vue` 的 ingestMaterial 当前只调用 computeFileSha256，提交时发送 evidenceSha256；未见原图上传。`confirmSlotAudit` 根据客户端哈希写 evidences。

第三方 HTML 已存全文，不代表人工截图也已存原件。真实材料接入前，必须让服务端取得图片内容、计算哈希并保存可恢复原件。只持有一串哈希无法在页面丢失后复核比赛记录。

### 3.2 六席校对不能直接承接单人历史

现有页面固定六席且逐一要求昵称和名次。一个玩家的个人历史截图通常只证明该玩家的一条参赛结果，不能为凑齐六席生成其余玩家。

新增“个人逐局材料”入口，复用现有导入与 verifyMatch 服务；六席场次校对保留为独立入口。不要为单人材料捏造完整赛事。

### 3.3 第三方窗口信息仍可完善

hokace 页面公开有版本标签和“7 日对局快照”文字；当前 Astro 解析分支只取卡片指标。应保留来源明示的版本和窗口文本，但仍不能从标签推导精确 UTC 起止或数据截止时间。

本轮应修正“页面完全未公布窗口”的过度表述：**公布了窗口描述，但精确时间边界未确认**。采集时间与数据截止时间继续分列。

## 4. 工作包与实施顺序

### W1：个人材料采集规范与原件入库（优先）

在没有真实材料时也可先完成工程，测试仅使用明确标注的 fixtures，不能将其用于 V07。

新增或复用管理端上传接口，例如 `POST /api/v1/admin/evidences`，具体名称沿用项目风格：

- 输入真实文件与最小元信息：来源类型、材料采集时间、提供人内部标识、允许使用范围。
- 服务端校验格式和大小，计算 SHA256，保存原始字节与 MIME、字节数、存储位置；客户端哈希仅作传输校验参考。
- 在现有 PostgreSQL/文件存储能力中选择简单可维护的实现；原件和元信息写入失败不能返回成功。数据库外文件需明确失败清理与备份方法。
- 按内容去重，但同一原图可以关联多条逐局记录；裁剪图记录与原图关系及各自哈希。
- 返回 evidenceId 和 PENDING 状态。上传不等于核验，不自动产生有效战绩。
- 管理端可鉴权预览/下载原件；公开页面只展示脱敏来源摘要，不暴露账号敏感信息或管理员凭证。
- 人工截图与 raw_materials 建立关联或独立受控存储均可，但必须有从战绩回到原件的路径。
- 所有核验入口统一要求原件可恢复、材料状态有效；不得仅凭任意 64 位字符串创建“完整证据”。旧只有哈希的材料明确标记原件缺失。

### W2：单人逐局导入与核验页面

工作流：上传原件 → 身份匹配 → 录入候选 → 原图对照 → 提交待核验 → 人工确认 → 新版本生效。

必需语义：

| 字段 | 规则 |
|---|---|
| playerId | 绑定稳定内部身份；昵称不是唯一身份 |
| 来源内 UID/区服 | 材料能证明才填写；未确认则保留临时身份，不强行合并 |
| matchTime | 来自材料，明确时区；仅有相对时间且无法可靠还原时保持待核验 |
| mode / playerCount | 按材料和已确认规则填写；不把所有模式一律当六人局 |
| finalRank | 材料中的名次，整数且符合该模式范围 |
| evidenceId | 指向可恢复原件；多条记录需有页码/图片区域/材料行等定位 |
| 外部对局 ID | 原文有则保留；无则受控证据键，不制造“官方流水号” |
| 阵容、棋手、积分、回合 | 可选，原文缺失为 null，不猜测 |
| availableAt | 由服务端实际核验时刻生成，不能让表单回填过去日期 |

交互要求：

1. 原图与候选并排，支持放大；OCR 如使用只辅助录入，低置信度和无法识别字段需明确提示。
2. 支持逐条确认/驳回及原因；操作者来自已有管理鉴权流程，不让任意文本冒充身份来源。
3. 昵称变更和同名玩家展示确认信息；不确定身份不能自动加入已知选手历史。
4. 复用 SCD-2 更正机制，保留历史；重复提交不产生新计数。
5. 六席入口移除“可不上传材料”误导文案；两种入口均遵循证据要求。

### W3：完成 V07 真实链路及独立复算

先在隔离验收环境导入获准真实材料；进入公开业务库须符合实际授权范围。不要再次清空或重新生成业务库。

逐条建立核对表：材料编号 → evidenceId → playerId → match recordKey/revision → 时间/模式/名次 → 核验人/核验时刻 → API 记录 → 页面。

至少 5 条真实参赛记录；这是最低链路验收量，不是判断玩家实力所需的统计样本量。不因场次数不足虚构记录或只挑高胜率玩家。

独立核对者从原图手工读取名次，计算 N、夺冠次数、前三次数和名次总和，再与 SQL、API、UI 对照。截图若只有个人全赛季汇总，不能拿它验证局部 5 局的比例，更不能由汇总反推逐局名次。

验证重复导入、更正、历史截点和重启后数据一致。真实记录不足以触发某个错误分支时，用隔离 fixtures 验证该分支，并在报告中分开标注。

### W4：补齐 hokace 的可持续展示

- 保存页面公开的 snapshotVersion、windowText 和原文定位；精确 windowStart/windowEnd/dataCutoffAt 无依据仍为 null。
- 把“最后抓取成功”与“来源数据更新”分别展示；重新抓取旧页面不得伪装数据已更新。
- 不因 card data-id 存在就假定跨版本永久稳定；对比两个真实快照，如结构可识别则保留结构键和来源版本映射，不按同名归并。
- 联网验收保存原文、哈希和对照结果。上游失败必须令“真实接入验收”明确 FAILED/BLOCKED，不能因错误处理正确而将该验收测试算通过。
- 原文明确允许的范围内，记录使用依据；未确认的许可/更新 SLA 继续写未确认，不以技术抓取成功代表授权确认。
- 本阶段不自动新建长期定时任务。若实施定时同步，先记录获准频率、重试上限、互斥、失败告警规则及停用方式，再按项目部署授权执行。

### W5：浏览器五态与端到端验收

优先使用当前环境已有浏览器工具。无法安装自动化依赖时，可通过已有浏览器执行并留证；不能仅因缺少 Playwright 包就省略浏览器检查。确实没有可用工具时，明确标记未执行并提交人工步骤。

主要路由：`/`、`/roster`、`/players/:id`、`/lineups`、`/lineups/:id`、`/archive`、`/events/:id`、`/admin/verify`。

| 状态 | 构造方法（隔离环境） | 观察点 |
|---|---|---|
| 正常 | 获准真实记录/现有真实阵容；测试数据须标 fixture | 指标、来源、详情跳转、返回状态正确 |
| 空数据 | 空身份、无该窗口战绩 | null 显示为“暂无/—”，不变成 0% 或默认历史 |
| 失败 | 受控 API 超时/500/断连 | 明确失败、可重试，不拿静态数据兜底 |
| 过期 | 受控旧快照和同步失败 | 同时展示实际数据时间/采集时间、过期标识；不污染业务时间字段 |
| 筛选 | 搜索、模式、窗口、排序、快速切换 | URL/返回状态正确；旧响应不覆盖新筛选；空结果区别于失败 |

至少桌面 1440×900 和手机 390×844；记录键盘访问、表格横向滚动、截断文字、对比度、加载反馈、错误恢复和控制台异常。桌面与移动均覆盖列表、详情、核验关键流程，不要求每个页面机械重复全部五态。

一次完整核验演练必须真实操作上传、预览、待核验、确认、查看详情、刷新页面、复查指标；只有渲染截图不等于操作成功。

## 5. 项目方需要提供的最小材料包

资料暂缺不影响 W1/W2/W4/W5 的独立开发和隔离测试；W3 必须等真实材料，不能由等待时间推定授权。

- 一位或多位自愿提供材料的玩家，确认内部验收/公开展示的允许范围。
- 至少 5 条逐局截图，尽量连续；包含可核对的玩家归属、模式、时间、名次。可以多张图共同证明一条记录。
- 一份必要的身份说明（来源 UID/区服如可见），敏感凭证不提交。
- 原始截图文件；另存脱敏展示副本，不能只提供手工填写 CSV 或无法回溯的数字。
- 如已有正式 API 文档、合作说明或合法导出文件，一并提供；没有则按人工接入路线继续。

提供说明建议：材料提供人内部标识、允许用途、是否允许公开昵称与战绩、保存期限或撤回约定。无需在公开仓库保存个人授权原文或敏感原件。

报告必须分别说明：

1. 人工材料上传与核验工程：完成/未完成。

4. hokace 信息完整度和联网实测：真实结果、时间及限制。
5. 浏览器验收：已执行的页面、状态、设备和剩余问题。

### 阶段完成条件
