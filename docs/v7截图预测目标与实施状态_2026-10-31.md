# 截图预测目标与实施状态

用户已确认：输入为开赛前六人名单截图；建议仅涉及游戏内虚拟钻石/积分，不涉及现金或可兑现资产。

## 产品闭环

赛前截图上传 → OCR候选 → 人工确认六席与账号档案 → 截止时刻之前的历史特征 → 六人同场获胜概率 → 结合返奖口径及虚拟预算给分配建议 → 保存赛前快照 → 赛后核对冠军/完整排名 → 更新历史并评估预测。

预测时不能使用本场赛后成型阵容、本场结果或之后收录的数据。“某人历史登顶比例”不等于“这六人同场时他的获胜概率”。

## 当前已实现

- `/research/predict` 新增截图入口，复用鉴权原件上传，默认 INTERNAL_ONLY。支持PNG/JPEG/WebP。
- macOS本地Apple Vision OCR，不向外部模型发送图片；需要本机Swift工具链。其他系统明确返回OCR不可用，不伪造成功。最大2400万像素，单任务及超时限制。
- OCR保留文本、位置和识别分数，给出昵称匹配候选；相似度不是身份概率。人工逐席确认，缺人不补造，重复昵称需复核。
- 识别“回放/最终胜者/胜者阵容”等赛后线索，分析中保留阻断项；即使人为勾选赛前确认，也不会因此清除标记。
- 新增0013：截图草稿与分析快照两表；原件指纹绑定，原件隔离或改变后拒绝读取草稿。后补历史按实际入库可见时刻过滤，不回填至比赛日期。
- 以用户填写的实际截图采集时间为截止；同日历史没有精确开赛时间时保守排除。每次分析保存请求与结果，不覆盖旧结果。
- 展示已匹配档案的近7/30日来源样本、玩法选择标签的登顶次数/出场次数、作者专长评价及来源。
- 当前概率为null；虚拟分配状态为ABSTAIN、保留100%。不是已经完成的获胜概率模型或投比算法。

实现依据：[Apple VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)。本机真实原图已识别60行、7行昵称候选，并识别赛后标记；不是对未来赛前截图版式的准确率承诺。

## 历史数据口径修正

| 目标 | 最小结果信息 | 当前情况 |
|---|---|---|
| 冠军分类/登顶标签 | 完整六人名单 + 唯一冠军 | 已转写54场，但身份/模式/版本/赛果核验不足，未作为有效训练集 |
| 前三率、平均名次 | 需要相应最终名次 | 不能从冠军推断其余五人的名次；周报独立留存 |
| 来源选择标签登顶比例 | 该标签的全部已观察出场及冠军标签 | 可计算样本内次数和比例，不声明历史完整覆盖 |
| 最终成型阵容胜率 | 胜者和非胜者的最终成型阵容均需记录 | 当前非胜者最终阵容不齐，该指标为空 |
| 擅长阵容 | 同一确认账号、版本、阵容下足量独立逐局样本 | 不能由一次获胜或作者棋手评价认定 |

冠军预测不应继续把“必须1–6全名次”作为全部样本的唯一入口；六席+冠军可作为独立胜负标签通道。但冠军榜只有冠军、缺另外五位参赛者，仍不能当作完整六人训练样本。

现有129个来源昵称不等于129位确认真人；54场/324席不等于完整历史；34行周报不得再累计成逐局分母。具体档案和原图见 [数据库记录](v7选手玩法数据库与扩充记录_2026-10-31.md)。

## 后续执行顺序和验收标准

### 1. 优先补来源历史，不能只等用户上传

先处理作者10月23–29日这一连续窗口的日图（含上下篇），逐篇登记实际图数、比赛期号、场次与缺图，再扩展更早日期。当前只完成27日8场、28日7场、29日8场；28日第2场缺图。禁止预设每天必定8场，更不能把找到帖子当成赛果已经采集。

已发现35篇来源中12篇转写完成，23篇更早资料仍待处理；23–26日上下篇的可见图集本轮已补。使用原图/OCR辅助后逐条核对，保留冲突、未知和来源修订；不得直接把自动识别结果升级为有效赛果。

验收：按日列来源、实际场次数、缺图、名单/冠军完整性、核验状态；每个统计分子和分母能追到原图。对“全量”只能声明某个明确来源和窗口的覆盖，不能承诺所有选手生涯记录齐全。

### 2. 统一账号和玩法标签

建立账号、历史昵称、别名候选及确认依据；UID缺失时允许来源内临时档案，但不能跨昵称猜测合并。记录平台、区服、模式、版本与版本判断依据，无法确认则单独分组。

阵容字段分为初始计划、已知转型和最终成型；规范流派名称，原词永久保留。棋手（玉环、马可等）、英雄、阵容流派、天赋分别建关联。作者“专精”保留为评价，不直接成为模型事实。

验收：相同流派的别称经人工确认后归类，保留映射版本和证据；个人×阵容的出场、登顶、前三与均排分别标注可用性和样本数。

### 3. 形成可回测训练集

核验后的六席+冠军记录用于冠军分类；完整名次作为另一个可选目标。按游戏版本和模式区分，近期表现只取预测前已知记录，选手与阵容的小样本需要平滑，冷启动单独评估。

先比较六人等概率与简单历史基线，再评估加入近期状态、历史玩法适配和同场对手后的收益。按比赛时间划分训练/验证，整场不能跨集合；给出log loss、Brier（注明求和/平均口径）、校准情况、有效预测场数与未知身份覆盖率。

今天才获取的旧资料只能用于明确标注的回溯研究，不能冒充过去线上当时可用的预测。真正的赛前效果需保存后续赛前预测，等待赛后结果验证。

### 4. 再实现虚拟分配算法

需要六人校准概率、截图返奖倍率、倍率是否包含本金、可用虚拟预算、单场/单人限额及规则。倍率识别后仍须人工确认，不能把“返奖率”默认为某一种收益定义。

应允许保留部分或全部预算，不要求把六人概率直接归一化成投比；最高胜率不必然代表最合适的分配对象。输出依据、预算使用率和不确定性，不保证收益。缺概率校准、身份、倍率口径或预算时明确暂不分配。

**当前尚未实现：校准概率模型、返奖倍率结构化确认、预算输入和正式虚拟分配算法。现有ABSTAIN只是门控，不是这些功能的替代品。**

### 5. 持续更新与复盘

比赛完成后关联赛前分析及赛后原件，核验冠军/名次，记录纠错与版本变化。统计预测命中和概率误差，展示数据更新时间与覆盖缺口。持续采集未验证前保持人工触发口径，不标实时。
