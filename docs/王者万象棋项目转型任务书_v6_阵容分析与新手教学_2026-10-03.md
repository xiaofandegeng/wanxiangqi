# 王者万象棋项目转型任务书 v6：阵容分析与新手教学

日期：2026-10-03  
交付对象：开发 AI、内容编辑、验收人员  
任务类型：原项目整体转型；本文件是当前开发范围的唯一任务书。v2—v5 中赛事、个人战绩、实时预测及 V07 材料验收要求终止，不再作为新产品上线前置条件。

## 1. 产品目标与范围

产品暂定名：**王者万象棋阵容研习站**。

帮助没有自走棋经验的玩家，从认识界面和卡牌开始，学会选择阵容、判断来牌、合理花费能量、过渡稳血、操作技能联动、成型与变阵，并理解阵容统计的适用范围。

成功标准：新手看完基础课程，能选出一套适合自己的阵容，知道第一局每个阶段要做什么；遇到核心不来、禁用阵营、缺装备或持续掉血时，有明确替代路线。产品必须解释“为什么这样做、什么条件下做、失败时怎么改”，不能只给最终七张英雄与一段长攻略。

首期围绕标准万象大赛教学，排位/其他模式必须明确区分适用性。钻石狂潮等不同规则模式暂不混入课程和统计。采用资料定期更新、编辑审核与版本维护，不依赖比赛实时接口、客户端持续运行、个人战绩上传。

继续使用现有 Vue 3、TypeScript、Vite 与 PostgreSQL。正式环境 PostgreSQL 唯一权威、数据失败不伪造的原则保留。不得为转型同时运行两套公开产品、两套阵容详情或第二套 JSON 权威库。

### 核心能力

| 用户问题 | 产品必须给出的结果 |
|---|---|
| 我刚开始玩，先学什么？ | 有顺序的学习路径、图解术语、短练习与第一局指引 |
| 现在有哪些热门或适合新手的阵容？ | 按版本、模式、难度筛选；热度、表现、新手适合度分开展示 |
| 这套为什么强？ | 输出/成长/资源/保护引擎、关键触发关系及条件 |
| 先拿谁、先上谁，谁只是过渡？ | 条件化的买牌、上阵、保留、回手、出售顺序 |
| 血掉得快怎么办？ | 止损判断、当回合可执行动作、资源预算和调整原因 |
| 怎么快速成型？ | 最小可用结构、核心缺失替补、拍卖目标、转阵边界 |
| 英雄技能怎么利用？ | 卡牌效果与战斗技能区别、触发时机、操作顺序和失败示例 |
| 数据可信吗？ | 来源、版本、窗口、样本单位、缺失/过期提示与计算口径 |

## 2. 调研依据与不能照搬的内容

### 已检查来源

1. **官网新手指引**：[官方专区](https://wxq.qq.com/cp/a202609xszy/index.html)。2026-10-03只读获取公开页面，标题为“新手指引—万象启航入门指南/基础规则/入门阵容教学”。页面包含基本对局规则、棋手技能与秘技、英雄牌、天赋、能量、竞拍，并提供入门阵容与多种教学形式。此页适合作为基础课程的第一方入口；上线前仍须逐项确认版本和适用模式。
2. **官网主站**：[官方主站](https://wxq.qq.com/cp/a20260707sfgw/index.html)。提供棋手/卡牌资料及攻略、新手专区入口，可研究其公开内容资源；页面入口不等于完整开放数据 API。使用资源要遵循许可，未确认许可的图片/视频保留原站链接，不整站复制。
3. **阵容统计来源**：[hokace 阵容工作台](https://hokace.wiki/zh/lineups/)。本轮页面显示 v260924、7日快照、35种阵容结构，提供核心英雄及登顶/前三/平均名次等指标，并说明部分结构样本重叠。这是第三方快照，不是官方全服实时统计。当前项目已有同步与原文存证能力，可复用。
4. **另一个统计候选**：[万象棋大数据](https://www.datawxq.com/explorer)。前轮实测有 v260930 与逐局阵容展示，但覆盖范围、API授权和玩家身份不完整。本轮只列为待验证来源，不为首期依赖，不恢复带签名密钥的旧混合赛事同步。

### 必须处理的资料冲突

公开攻略对拍卖回合、经验增加、升本方式存在冲突。官网新手专区明确描述可花能量提升棋手等级；不能照搬“无法花能量升级”的其他文章。拍卖固定回合、经验表、商店概率、技能数值等必须经过当前版本第一方资料/客户端核对才写入规则库。

不得直接套用金铲铲或其他自走棋的利息、升星、搜牌和人口规则。旧项目出现过“三星”等表述，新产品应以万象棋自身术语和机制为准。

**研究结论：**教学内容有第一方资料入口、阵容有可用第三方快照，转型具备数据基础。2026-10-03读取到的 v260924 快照不能自动视为当天最新版本；当前版本未核实的内容需注明适用版本，不能冠名“当前最强”。

## 3. 信息架构：每类内容只有一个维护位置

公开主导航固定为：首页、新手学堂、阵容库、资料库、版本动态。阵容统计放在阵容库内，避免另设一个重复阵容列表。管理端不出现在新手主导航。

|---|---|---|
| `/` | 学习与选阵容入口 | 首次访问突出“从零开始”；展示已核实版本、更新日期、新手推荐与热门阵容摘要 |
| `/learn` | 学习路径 | 阶段、先修课、学习目标、完成进度 |
| `/learn/:slug` | 单课 | 规则图解、操作顺序、案例、练习与下一课 |

| `/lineups/:slug` | 唯一阵容详情 | 阵容组成、阶段操作、技能联动、站位、替补、统计、案例与来源 |
| `/library` | 统一资料搜索 | 英雄、棋手、装备、效果牌、天赋、阵营、机制分类 |

阵容卡片只给摘要并链接详情；课程引用英雄/术语时链接资料库；资料库列出关联阵容。共用同一英雄ID、同一规则条目、同一阵容ID。不能为了每篇攻略复制一份英雄技能或规则正文。

## 4. 新手教学：从认识规则到独立决策

### 学习阶段

| 阶段 | 必讲内容 | 学完能做什么 |
|---|---|---|
| A. 第一次进入游戏 | 胜负、生命值、回合、棋手与英雄区别；手牌/商店/战场/备战区；操作按钮 | 看懂界面，完成买牌、打出、查看技能等基础操作 |
| B. 认识成长和资源 | 能量用途、收入与卖牌、棋手等级/英雄等级、觉醒、上阵人数、牌库与可获得卡牌 | 解释为何现在买牌、刷新、升级或保留资源 |
| C. 认识卡牌效果 | 登场、整备、开团等版本已确认词条；效果牌、天赋、装备与秘技 | 能判断触发条件和操作顺序，而非只看战力数字 |
| D. 学会过渡稳血 | 前排/输出/功能位；临时阵容、关键低阶牌、临时装备、何时花资源止损 | 不为追最终阵容而空场或无预算搜牌 |
| E. 玩会第一套阵容 | 开局条件、阶段目标、核心到场、最低成型、缺牌替补、站位 | 独立打完一局并解释主要决策 |
| F. 学会变阵与复盘 | 禁用/同行/缺装备/来牌变化；看对手；拍卖取舍；输在哪里 | 用条件改变计划，找出下一局要改的一件事 |

### 单课统一结构

学习目标 → 先修知识 → 一张规则图 → 具体操作 → 为什么 → 常见错误 → 情境练习 → 答案解释 → 下一课/应用阵容。正文先用白话，术语点开即可看解释。禁止把几十个术语堆给新手自行理解。

提供两种观看层次：“第一次玩”显示基础动作，“我已理解规则”展开细节。进度与收藏先用本地存储，不新增游戏登录和账号绑定；浏览器不允许存储时仍可使用课程。

### 情境练习

必须围绕实际决策，如“核心未到但前排已不足”“预算有限且下一节点需要资源”“关键触发英雄未觉醒”“阵营被禁”。给出状态、候选动作、正确原因、其他动作的代价。教学快照明确标“教学情境”，不得统计为真实对局。

用户主动填写本局状态时可给**规则明确的情境提示**，首期仅支持已审核题目与条件分支。不开发读取游戏画面的实时教练，不宣称自动判断下一对手或胜率。

## 5. 阵容详情：操作手册而不是终局名单

每套阵容必须按以下模板录入，字段缺失阻止发布，不用AI套话填充。

### 5.1 定阵条件与最低可用结构

- 适用游戏版本、模式、棋手及熟练度；依赖特定天赋/装备/英雄的程度。
- 可以考虑玩、优先玩、应放弃的明确条件；禁用阵营处理。
- 核心输出、前排、成长引擎、资源引擎、保护和控制分别是谁、贡献是什么。
- 区分“最小可用结构”“常规成型”“理想上限”。低概率完整神装不作为新手必须目标。
- 每张卡明确角色：过渡牌/必需核心/功能替补/后期上限；核心到位前后的替换关系。

### 5.2 条件化阶段操作

| 字段 | 要求 |
|---|---|
| 阶段与触发 | 开局/第一关键节点/中期/成型/后期；可附已核实回合，但不只用固定回合判断 |
| 当前目标 | 稳血、找核心、开技能、补保护、提高上限，优先级只保留必要项目 |
| 买/留/上/回手/卖 | 每类动作分别写清对象，不能把买牌等同上阵 |
| 操作顺序 | 先触发什么效果、再使用什么卡、何时合成/回手/换位 |
| 资源预算 | 本阶段最多愿意投入多少、保留多少、何时停止；数值依据与适用条件必须可追溯 |
| 装备/效果牌/天赋 | 当前急需项、可替代项、应保留项和理由 |
| 分支 | 核心来了/未到；血量危险/健康；前排够/不足；装备不适配/可以转阵 |
| 成功与失败信号 | 如何判断稳住或成型失败；下一步改什么 |

规则数字与经验建议分列。未经版本验证的回合不能写“第X回合必升本、必拿某卡”。“看情况、适当搜牌、注意运营”不构成合格步骤。

### 5.3 稳血和快速成型

每套至少覆盖三种止损分支：缺核心、缺前排/保护、关键装备不来。解释血量、资源和即时质量如何共同影响决策；不输出“还有X滴血必安全”这种无依据阈值。

“快速成型”应解释减少无效买牌、缩小搜索目标、选择可用替补、利用已确认成长联动。区分提升成型效率与保证胡牌；不能保证某回合一定凑齐。

### 5.4 英雄与棋手技能教学

分别说明：英雄牌打出效果、非战斗触发效果、英雄战斗技能、棋手主动/被动技能、秘技及专属天赋。按当前版本建立关联，防止同名角色作为棋手和英雄时混用。

每套至少一段完整技能操作链：触发前提 → 动作1 → 发生的效果 → 动作2 → 收益 → 中断条件/失败例。用动作序列与棋盘/手牌变化图表达；未验证的“无限循环”不作为事实发布。

### 5.5 站位与变阵

提供棋盘图，标前排、主输出、保护位、触发相邻关系、目标选择条件。至少给默认站位和一种针对站位，并解释变化原因。格子关系应由真实机制支持，不套用其他游戏棋盘。

替补不是泛称“同定位都可以”：明确替谁、损失哪条联动、要补什么、何时卖旧牌、是否需转装备。提供禁用阵营与多人抢核心的替代路线，不承诺能读取实时公共牌库。

### 5.6 实战案例

每套至少一个有出处的案例，可用编辑原创图解与来源视频时间点讲解。首批至少两套同时覆盖成功与失败案例。标出实际状态、候选动作、选择理由、结果和不能推广的偶然条件。

不复制整篇攻略或下载搬运完整视频。允许原创解读、短引用及来源链接；素材许可和允许展示范围登记到来源记录。

## 6. 阵容统计与推荐口径

**不再统计真实玩家个人胜率。** 统计对象为来源公布的阵容结构、棋手、英雄、装备等，来源各自独立展示。

### 指标规则

| 指标 | 定义与限制 |
|---|---|
| 登顶率 | 已知样本单位下第一名样本数 / 有效样本数；来源只公布率则保留“来源公布”，不反推整数分子 |
| 前三率 | 同一口径下名次≤3样本数 / 有效样本数；六人制口径不得套四人进前四 |
| 平均名次 | 相同版本/模式/窗口的名次均值；与其他来源不直接混合 |
| 出现率/热度 | 必须有覆盖范围与分母；结构重叠时不能要求占比合计100%，不能用单套样本量冒充全服出现率 |
| 新手适合度 | 编辑依据操作复杂度、依赖性、替补弹性说明理由；不是胜率，不做无来源数值评分 |
| 难度 | 低/中/高，附具体操作要求；高热度不等于适合新手 |
| 稳血能力/成型要求 | 教学评价，写依据和限制，不包装为统计推断或稳赢结论 |

显示来源名、sourceId、原始链接、版本、模式、窗口、样本单位、样本量、数据截止时间、抓取时间。抓取今天不等于数据今天。来源未给绝对窗口日期时保留其“近7日”原文及观察时间，禁止伪造日期边界。

缺失 → null → “暂无统计”；小样本提示；过期显示适用旧版本；同步失败保留上次快照并明确状态。样本量未知不能标“大样本可靠”。同时包含热度和表现时分别提供排序，首期不设计混合综合指数。

“当前热门”仅在已核实当前版本与来源口径一致时使用。否则栏目名为“最新可用快照/适用X版本”。“新手推荐”可在无统计时基于已审核教学理由发布，明确编辑推荐，不制造热度。

不同来源的比率不得简单平均；不同窗口、不同模式、不同结构定义不得拼接。只有同一统计总体、可去重记录且有完整分子/分母才允许本地复算。首期以来源快照为主，不重建全服对局池。

## 7. 内容模型、存储与接口

### 7.1 单一事实源

沿用来源登记、raw_materials原文/哈希/解析版本、sync_jobs成功失败台账及事务提交。新增内容模型，建议如下（可以按现有仓储惯例调整表名，但责任不能合并为大段不可校验正文）：

| 模型 | 关键责任 |
|---|---|
| game_versions | 版本ID、官方依据、生效时刻、当前/历史状态；版本日期与抓取日期分离 |
| catalog_entities + catalog_entity_revisions | 英雄/棋手/装备/牌/天赋/阵营稳定ID、类型、版本化事实、来源及核验状态 |
| mechanics + mechanic_revisions | 唯一规则条目、适用模式/版本、结构化参数、原始说明及来源 |
| lineups + lineup_revisions | 稳定阵容ID/slug、版本化教学内容、阶段动作、依赖条件、难度与发布状态 |
| lineup_components | 阵容版本、实体ID、角色、必需性、替补关系、站位依赖 |
| lineup_snapshot_links | 阵容与来源结构键的显式映射；未匹配的快照不自动编成攻略 |
| lineup_snapshots | 保留原有来源快照语义并补齐真实必要字段；原始比率/单位保留，归一化必须可审计 |
| lessons + lesson_revisions + lesson_dependencies | 课程顺序、先修图、学习目标、引用实体/规则、版本化练习 |
| scenarios | 教学情境、已知状态、条件分支、反馈和来源；与实战样本隔离 |
| content_references + content_review_log | 每项引用、素材范围、审核记录、修改/回滚理由 |
| patch_notes + content_impacts | 官方更新、受影响英雄/课程/阵容、待复核状态 |

ID不能以可变名称做主键；同名实体按种类区别。相同阵容可有多个历史教学版本和多个来源快照，但只有一个公开阵容实体。

### 7.2 发布流程

草稿 → 待审核 → 发布 → 待版本复核/退役。原文事实、编辑建议和教学情境分类型。原件存在检查、内部材料不公开等约束继续适用于新内容引用。不能上传即自动发布。

管理员修改保存到数据库，重启后保持；发布修改与审核日志在同一事务；回滚生成可追踪的新版本，不覆盖历史。引用循环、先修循环、不存在实体、跨版本强绑定和缺少必填章节需拒绝。

AI可用于草稿整理和措辞，不自动生成技能数值、统计、版本状态或实战结论。首期不需要面向用户的自由问答机器人。

### 7.3 API范围

公开提供阵容列表/详情/统计、课程路径/详情、资料搜索/详情、规则、版本动态。可继续使用 `/api/v1/lineups`，但新的返回契约以稳定阵容为根，统计作为来源快照子对象；前后端同步升级，不同时维护旧快照页契约和另一套攻略页契约。

示意：`GET /api/v1/learn`、`/lessons/:slug`、`/catalog`、`/catalog/:kind/:slug`、`/mechanics/:slug`、`/versions`、`/updates`。

管理端提供内容编辑、审核/发布、版本复核、来源同步、原文审计，保留鉴权。health/ready继续体现真实库连接，公开健康接口去掉旧玩家/赛事业务计数，敏感原文只能在管理端获取。

### 7.4 更新机制

来源手动同步和定时同步使用同一服务路径；定时频率依据来源条件配置，不承诺秒级。防重叠任务、超时、有限重试、失败不推进成功时间。禁止用户每打开页面直接抓第三方网站。

发现新版本时记录更新并标记依赖内容待复核；旧指南不自动改为新版本。历史内容可查看，默认列表不混排成当前推荐。来源消失时仍可展示已存证历史资料及失效提示。

## 10. 首期内容交付量与发布门槛

这些数量是开发验收目标，不是声称已有内容：

1. 不少于10个有顺序的基础课程，覆盖§4所有阶段；不少于20个已核实基础术语/规则条目。
2. 不少于6套经过审核的阵容手册，其中至少3套依据低操作负担/替补弹性选为新手路线。不能把官网标“高上限”的阵容直接评为低难度。
3. 首批阵容涉及的所有必需英雄、棋手、装备/效果牌必须有可引用资料；至少覆盖20个英雄、6个棋手的必要条目。按实际第一批阵容补足，不为凑数加入无出处实体。
4. 至少8个决策情境；至少2套带成功与失败的完整复盘；每套不少于一个有出处操作案例。
5. 至少一个真实统计来源可以独立同步、存证、重启读取；统计不足不阻止合格教学内容发布，但上线说明必须写清统计覆盖范围。
6. 至少一套阵容完整覆盖“选阵条件→开局→过渡→稳血→成型→技能链→站位→缺牌变阵→复盘”，由新手走查验证可理解。

内容达不到数量/核验要求时如实写缺口，不生成无依据攻略或复用同一文章改名凑数。开发骨架完成与内容可用分别报告。
